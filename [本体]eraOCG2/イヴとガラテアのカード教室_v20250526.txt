@N2_関数

ガ：お姉さまは『関数』が何かは知っていますか？
イ：ええっと・・・xとかtとかだったかしら？
ガ：それは数式ですね！　大体合ってます！
　　『関数』とは言ってしまえば命令ですね！
　　お姉さまは歩く時はどうしていますか？
イ：え？　右足を出して、左足を出して・・・
ガ：そうです！　それをロボットにやらせようとするとどうなりますか？
イ：それは・・・一個ずつ命令するしか無いんじゃない？
ガ：でもそれって面倒じゃないですか？
　　そこで、『関数』を使います！

    @Walk
    命令,右足を出す
    命令,左足を出す

ガ：これが『歩く』の関数です！

イ："Walk"が関数の名前なのは分かるんだけど、その前の"@"はなんなの？
ガ：これは関数に付いてるものですね！　カテゴリのようなものです！
　　そしてこれを使うには、こうします！

    CALL Walk

ガ：これで動くようになりました！
　　"CALL"は関数の処理を呼び出すことができます！
イ：でもこれって二歩進んでるだけよね？
　　長く歩くなら何度も"CALL"って書かなきゃいけないの？
ガ：そこに気が付くとはさすがはお姉さまです！
　　面倒だしコードが長くなりますよね？　なのでこうします！

    @Walk(リピート回数)
    #DIM DYNAMIC リピート回数

    REPEAT リピート回数
        命令,右足を出す
        命令,左足を出す
    REND

イ：何かいっぱい増えた・・・
ガ：一個ずつ見て行きましょう！
　　まずは"リピート回数"ですが、これは"数列変数"と呼ばれるものです！
　　ここには数字だけが入ります！
ガ：そして" #DIM DYNAMIC"！
　　これは変数の定義ですね！　これが無いとゲームに怒られます！
ガ：最後に"REPEAT"！　これはそのまま繰り返す処理です！
　　"REND"までの処理を指定回数繰り返します！
ガ：そしてこれらはこう使います！

    CALL Walk(5)

ガ：これで"リピート回数"には"5"が入った状態で"@Walk"が呼び出されます！
　　そして、歩く処理が５回！　つまりは１０歩歩くようになりました！
イ：なるほどね。
　　ところで、これはカードを作るのにどれだけ重要なのかしら？
ガ：根本的にはバベルですが、実際にはカノーネレベルで必要ありません！
イ：ええ・・・じゃあ何で教えたの？
ガ：システムへの理解を深めることはカードへの理解に繋がりますからね！
　　でも基本は既存のカードの継ぎ接ぎで大丈夫だと思います！
イ：そうなんだ。
ガ：では次は"IF文"の授業を始めます！
イ：まだ続くの？

@N3_IF文

イ："IF文"って何よ。
ガ：簡単に言えば、『もしもＡが条件を満たしていたら』を実行します！
イ：・・・・・・？
ガ：軽く例を出しましょうか！

    IF ギルス == 女
        ギルス = お姉さま
    ENDIF

ガ：これは、『もし"ギルス"が"女"だったら、"ギルス"は"お姉さま"になる』というコードです！
イ：・・・考えたくないわね。
ガ：それはどちらの意味でですか？
イ：どっちもよ！
　　・・・ん？　この最初の『ギルス == 女』なんだけど、なんで『=』が２つ付いてるの？
　　兄さんに習った時は１つだったけど・・・
ガ：お姉さま！
イ：何？
ガ：今まで覚えた算術はちょっとだけ忘れてください！
イ：ええ？
ガ：そしてこちらを御覧ください！

    IF アウラムの身長 >= イヴの身長
        アウラム×イヴ
    ELSEIF アウラムの身長 < イヴの身長
        イヴ×アウラム
    ENDIF

イ：私が攻め・・・悪くないわね。
ガ：これは、『"アウラムの身長"が"イヴの身長"以上だったら、"アウラム×イヴ"』。
　　『"アウラムの身長"が"イヴの身長"より小さかったら、"イヴ×アウラム"』というコードもどきです！
　　見ての通り、不等号の使い方は今までのものと一緒です！
イ：じゃあなんでさっき忘れろって言ったの？
ガ：さっきの『==』も同じ要領です！
　　『>』『<』だったら"以上"、"以下"、　『=』だったら"同値"と覚えるといいと思います！
イ：なるほどね・・・
　　じゃあ『ギルス = お姉さま』は何なの？　一つだけだけど。
ガ：これは"代入"ですね！　これによって『ギルスはお姉さま』ということになります！
　　ちなみに、代入は基本的に上書きなので、『ギルスはお姉さま』ですけれど、『ギルスは女』ではありません！
イ：え、ええ？
ガ：『x=3』と『x=6』の場合の問題の答えを求めるのと同じです！
イ：あ、あー・・・なるほど。
　　同じ関数の中に違うものが入っているのね。
ガ：慣れるまでに時間はかかると思いますが、お姉さまなら簡単なはずです！
イ：さすがに買い被りすぎよ。
ガ：この"IF文"はこれからあらゆる場所で出て来るので、しっかり復習しておいてくださいね！
イ：復習の時間は？
ガ：ありません！　すぐに次へ行きます！

@C1_サーチ（手札に加える）

ガ：それでは実際にカードを見ながら勉強していきましょう！
　　今回のお題は『サーチ』です！

イ：えっと・・・『デュエル関連の中にある、CARDの中にある、汎用カード群の中にある、汎用魔法カードの中にある、激レアの中にある、増援を開く』でいいかしら？

　　・・・ねえ、カテゴリ『なし』ってどういうこと？　無いなら書かなくてよくない？
ガ：『カテゴリが無いカード』を指定しているカードもあるので、しっかり付けておきましょう！
イ：なるほど。


ガ：次はその下の『CARD』関数なんですけど・・・
イ：歯切れが悪いわね。
ガ：ぶっちゃけ今は言うことがありません！
　　モンスターなら色々書いてあるんですけどね。
イ：じゃあどうするの？　他のカードでも見る？
ガ：こういう時話題がずれるのはよくありません！
　　またおいおい説明します！
イ：おいおい。


ガ：次が大事な『CARD_EXPLANATION』関数！
　　効果テキストです！
イ：やっぱ増援のテキストって短いわね・・・
ガ：ここを間違えると不具合扱いされるので、しっかり書いておきましょう！
イ：はーい。
　　この『CARD_ABLE』ってヤツはなんなの？
ガ：それは発動済みかどうかとか、どの効果を使っているかを視認しやすくするものですね。
　　ゲーム内だと分かりやすいと思います。
イ：ふーん。


ガ：その次がはちゃめちゃに大事な『CARDCAN』関数！
　　発動条件です！
イ：色々書いてあるわね・・・
ガ：重要なのは『魔罠起動』『手札起動』より下なので、そこから見て行きましょう！
　　この２つが何かはわかりますか？
イ：うーん、『魔法＆罠ゾーンでの発動』と『手札からの発動』かしら？
ガ：さすがお姉さま！
イ：いや見ての通りでしょうに・・・
ガ：ではさっさと見て行きましょう！

    SIF メインフェイズ != 1
		RETURN 0

ガ：これは『メインフェイズかどうか』の確認ですね！
　　メインフェイズじゃないと『RETURN 0』、発動不可です！
イ：なんで？
ガ：そういうシステムだからです！
イ：なるほど。
　　・・・この『SIF』ってやつは何かしら？
ガ：それは短い『IF』ですね！　『Short IF』で覚えるといいと思います！
　　これは『IF』と違って『ENDIF』が必要ありませんが、そのすぐ下の処理しか行われません！
イ：つまり、ここだと『RETURN 0』しか処理されないってこと？
ガ：さすおね！　その通りです！
イ：ふーん・・・メインフェイズだと、メインフェイズは１なの？
ガ：はい！
イ：そういうシステムだから？
ガ：はい！

ガ：次はコレです！

    SIF ターンプレイヤー != 決闘者
		RETURN 0

イ：ターンプレイヤーが・・・『決闘者』？
　　みんな決闘者じゃないの？
ガ：この『決闘者』というのは"文字列変数"です！
　　今回は"自分"か"相手"が入っていますね！
ガ："自分"というのは『あなた』、つまりはプレイヤーで、
　　"相手"というのはＮＰＣですね！
イ：つまり、どういうこと？
ガ：・・・よく考えたらこの説明は必要ありませんでした！
　　『決闘者』はカードの発動者のことです！
イ：発動しているのがターンプレイヤーじゃないとダメってことね。
ガ：さすおね！
イ：それ気に入ったの？

ガ：最後にこれですが・・・少し長くなるのであっさり終わらせます！

    CALL FULLRESET
	効果範囲デッキ = 1
	効果条件種族 = 戦士族
	CALL 効果条件レベル_ADV(4, "以下")
	CALL CARD_CHECK_ADV(決闘者,種類,ゾーン,場所)
	SIF RESULT != 1
		RETURN 0

イ：うん・・・うん・・・？
ガ：これは『指定した範囲の、指定した条件のカードをチェック』する処理です！
イ：あ、あー。
　　"デッキ"の"戦士族"の"レベル４以下"を探しているのね？
ガ：さすおね！
　　理解が早くて最高です！
ガ：最初の『FULLRESET』で範囲と条件のリセット。
　　最後の『CARD_CHECK_ADV』で実際にチェックをしています！
　　該当するカードがあれば、『RESULT』には"１"が入っています！
イ：なるほど、『FULLRESET』が無いと別のカードの処理が持ち越されちゃうのね。
ガ：その通りです！
　　『FULLRESET』はどこででも使うので、とりあえず書いておく癖を付けましょう！


ガ：最後がとんでもなく重要な『CARDEFFECT』関数です！
　　実際のカードの効果を処理します！
イ：むしろここが一番重要じゃないの？
ガ：カードに重要じゃない場所なんてありませんよ？
イ：それもそうね。

ガ：それでは最初は『CARD_CHOICE』です！
　　「～を発動しますか？」ってやつですね！
イ：あー、これがアレなのね。
ガ：関数にある"場所"の後ろに"70011"があるのが見えますね？
イ：うん。
ガ：これは『カードID』です！
　　ここを間違えると他のカードの名前で確認されます！
ガ：たとえば"70003"と入れると、「サンダーボルトを発動しますか？」と聞かれます！
イ：それでも効果は《増援》なんでしょ？　すごいややこしくなるわね・・・
ガ：はい！　なので必ず！絶対に！死んでも！そのカードのIDを入れてください！
イ：私たち二人とも一回死んでるようなものじゃない。
ガ：そうでした！

ガ：次は『CARD_DISPOSE』です！
　　カードを移動させる処理ですね！
イ：・・・墓地へ送る処理ってこと？
ガ：概ねその認識で大丈夫です！
　　基本的に魔法カードは発動した時にこれで墓地へ送ります！
イ：無いとどうなるの？
ガ：増援が何度でも使えて禁止カードになります！
イ：なるほど。

ガ：さて！　ついに今回の本題！
　　カードを手札に加える『CARD_ADD』関数です！
イ：『CARD_ADD_BASIC』じゃなくて？
ガ：はい！　実は『CARD_ADD』関数には『BASIC』と『ADV』の２種類があります！
　　使い方は大して変わらないので、実際の例を見てみましょう！

    （CARD_ADD_BASIC）
    CALL FULLRESET
    効果条件種族 = 戦士族
    CALL 効果条件レベル_ADV(4, "以下")
    CALL CARD_ADD_BASIC(決闘者,"デッキ",ゾーン,場所)

    （CARD_ADD_ADV）
    CALL FULLRESET
    効果範囲デッキ = 1
    効果条件種族 = 戦士族
    CALL 効果条件レベル_ADV(4, "以下")
    CALL CARD_ADD_ADV(決闘者,ゾーン,場所)

イ：・・・『BASIC』関数の中にあった"デッキ"が、『ADV』だと"効果範囲デッキ"になってるわね。
ガ：その通りです！
　　『BASIC』では１つの範囲しか見ることができませんが、『ADV』だと複数の範囲を見ることができます！
ガ：たとえば、『効果範囲墓地 = 1』と書き入れると、墓地からも回収できちゃいます！
イ：《戦士の生還》の存在価値が無くなるわね・・・
　　というかこれなら『BASIC』いらなくない？　『ADV』だけでよくない？
ガ：はい！そうですね！
　　存在価値が無いわけではないですが、基本は『ADV』だけでいいと思います！
イ：初期のバニラモンスターみたいね・・・


ガ：これにて「カードを手札に加える」処理の解説は終わりです！
イ：カード全体の解説をしてた気がするけど・・・まあ、間違いなく必要だったわね。
ガ：ですがこんなのは本の序の口！
　　まだまだカードに必要な処理はいっぱいありますよ！
イ：まあそうよね・・・
ガ：それじゃあ次も頑張っていきましょう！

効果条件レベル,20       ・・・  カードのレベルを条件に取る,＊２

効果条件攻撃力,20       ・・・  指定した値"以下"の攻撃力を条件に取る
効果条件以攻撃力,20     ・・・  指定した値"以上"の攻撃力を条件に取る

効果条件守備力,20       ・・・  指定した値"以下"の守備力を条件に取る
